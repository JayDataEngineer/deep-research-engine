## Project Overview

The Deep Research Engine is a config-driven multi-agent workflow engine that unifies 4 existing projects:

1. **Deep Research** - Multi-agent RAG research
2. **PDF Summarizer** - PDF processing  
3. **make-llmstxt** - Skill generation
4. **tracer** - Telegram ingestion with multimodal support

**Key Insight**: All 4 projects use the same `Ingestion → Drafter ↔ Critic → Neo4j → Synthesis` pattern. The engine makes this configurable via YAML.

---

## Architecture

```
Config (YAML) → Engine → LangGraph Workflow
                     ↓
        Ingestion → Drafter ↔ Critic → Neo4j → Synthesis
```

### Core Design Decisions

1. **Generic State** - 18 fields max (not 50+)
   - Workflow-specific data in `context` dict
   - See: `src/deep_research_engine/state/types.py`

2. **Pluggable Storage** - Optional backends
   - PDF: Just Memory
   - Telegram: Postgres + Neo4j + MongoDB + MinIO
   - See: `src/deep_research_engine/storage/`

3. **Worker ABC** - Uniform interface
   - All workers implement `execute(state, config) -> WorkerResult`
   - See: `src/deep_research_engine/workers/base.py`

4. **Config-Driven** - New workflow = new YAML
   - See: `configs/*.yaml`

### Graph Execution

**Goal**: Implement LangGraph workflow

**Files**:
```
src/deep_research_engine/graph/
├── builder.py              # build_workflow_graph(config)
└── nodes/
    ├── ingestion.py
    ├── drafter.py
    ├── critic.py
    ├── neo4j_builder.py
    └── synthesis.py
```

**Key Patterns**:
```python
from langgraph.graph import StateGraph, START, END
from deep_research_engine.state import EngineState

def build_workflow_graph(config):
    graph = StateGraph(EngineState)
    
    graph.add_node("ingestion", ingestion_node)
    graph.add_node("drafter", drafter_node)
    graph.add_node("critic", critic_node)
    graph.add_node("neo4j", neo4j_builder_node)
    graph.add_node("synthesis", synthesis_node)
    
    graph.add_edge(START, "ingestion")
    graph.add_edge("ingestion", "drafter")
    graph.add_edge("drafter", "critic")
    graph.add_conditional_edges(
        "critic",
        route_after_critic,
        {"pass": "neo4j", "revise": "drafter"}
    )
    graph.add_edge("neo4j", "synthesis")
    graph.add_edge("synthesis", END)
    
    return graph.compile()
```

## Best Practices

1. **Keep state minimal** - 18 fields max, use `context` for workflow-specific data
2. **Use storage abstraction** - Don't couple workers to specific backends
3. **Handle errors gracefully** - Return structured `WorkerResult` with error info
4. **Test thoroughly** - Unit tests for workers, integration tests for workflows
5. **Document configs** - Each YAML config should have comments
6. **Use type hints** - Required by mypy
7. **Log appropriately** - Use the logging utility
